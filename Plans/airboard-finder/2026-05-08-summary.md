TYPE: BRIEF

TITLE: AirBoardFinder — Telegram Flight Price Alert Bot
SLUG: airboard-finder

TASK_SUMMARY:
Build a single-process Python 3.12 Telegram bot that polls the Kiwi Tequila API every 60 minutes via APScheduler, compares found prices against user-defined watch thresholds stored in SQLite, and fires formatted Telegram alerts when a price drops to or below threshold. Users create and manage watches through three bot commands. A two-layered deduplication scheme (alerts_sent table + 5%-additional-drop rule) suppresses spam.

CONTEXT_SUMMARY:
Project CLAUDE.md at `CLAUDE.md` already defines the full tech stack, file layout, SQLite schema (3 tables), critical patterns, and debugging workflow. No existing source files are present yet — only CLAUDE.md. The project has no AGENTS.md, ARCHITECTURE.md, CONTRIBUTING.md, CHANGELOG.md, or any Python source. The global CLAUDE.md mandates those files be created before any development begins.

Key project-doc findings:
- Auth: `apiKey` HTTP header on `GET https://api.tequila.kiwi.com/v2/search` — never in the URL.
- SQLite threading rule: each thread (scheduler pool vs. Telegram handler threads) must open its own `sqlite3.connect()`. No shared module-level connection.
- `fast-flights` PyPI package is an approved fallback when Kiwi returns no results; must log a WARNING when it fires.
- Log file: `logs/bot.log`; database file: `data/airboard.db`.
- Entry point: `main.py`; modules under `bot/`: `handlers.py`, `scheduler.py`, `kiwi_client.py`, `db.py`, `formatter.py`.
- Tests run with `pytest`; coverage via `pytest --cov=bot --cov-report=term-missing`.

KEY_CONSTRAINTS:
- Authentication uses an `apiKey` HTTP header, not a query parameter. Never put the key in the URL string.
- An alert is only sent when: (1) no row exists in `alerts_sent` for this watch + price bucket, AND (2) the new price is at least 5% lower than the last alerted price. Removing either layer causes spam.
- Each thread must open its own `sqlite3.connect()` — never store a single connection as a module-level global.
- The `fast-flights` PyPI package breaks silently on protobuf schema changes. Use it only when Kiwi Tequila returns no results, and log a warning when the fallback fires.
- Global CLAUDE.md: No features beyond what was asked. No abstractions for single-use code (simplicity-first).
- Global CLAUDE.md: Before closing any task, `CONTRIBUTING.md`, `CHANGELOG.md`, `ARCHITECTURE.md`, and `docs/adr/` must exist and reflect current state.
- All credentials live in `.env`; a `.env.example` template is required.
- Python 3.12 runtime; python-telegram-bot v20; APScheduler; SQLite (no ORM).

ACCEPTANCE_CRITERIA:
- AC1: `/watch <origin> <destination> <date_from> <date_to> <max_price>` stores a watch row in SQLite and replies with a confirmation message including the watch ID.
- AC2: `/list` returns a formatted list of all active watches for the calling user (Telegram user ID scoped); empty-list case handled gracefully.
- AC3: `/delete <watch_id>` removes the specified watch and confirms deletion; rejects IDs that don't belong to the calling user.
- AC4: APScheduler job fires every 60 minutes, queries Kiwi Tequila for each active watch, and stores results in `price_history`.
- AC5: When a found price is at or below `max_price` AND deduplication passes both layers (alerts_sent check + 5%-drop rule), a Telegram message is sent containing route, price, and booking URL.
- AC6: No duplicate alert is sent for the same watch+price unless the new price is at least 5% lower than the previously alerted price.
- AC7: When Kiwi returns no results, `fast-flights` fallback is attempted and a WARNING is logged.
- AC8: All credentials (`TELEGRAM_TOKEN`, `KIWI_API_KEY`) are read from `.env`; a `.env.example` documents the required keys.
- AC9: `pytest` suite covers: DB operations (watches CRUD, deduplication logic), Kiwi client (mocked HTTP), alert formatter output.
- AC10: `logs/bot.log` captures INFO-level runtime events and DEBUG-level Kiwi API responses when `LOG_LEVEL=DEBUG` is set.

RECOMMENDED_APPROACH:
Scaffold the project structure first (all required files per global CLAUDE.md: `ARCHITECTURE.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, `docs/adr/`, `.env.example`, `requirements.txt`) before writing any bot logic. Implement the DB layer (`bot/db.py`) first with its own connection-per-call pattern, then the Kiwi client with header-based auth and fast-flights fallback, then handlers, then the scheduler job that ties them together.

Critical integration decision: python-telegram-bot v20 runs an `asyncio` event loop; APScheduler must be wired correctly. Use `AsyncIOScheduler` on the same event loop (preferred — simpler, no cross-thread alert posting) OR `BackgroundScheduler` with `asyncio.run_coroutine_threadsafe` for sending alerts back. The Planner must pick one and record it in `docs/adr/`.

Deduplication logic should live in `bot/db.py` as a single testable function.

OPEN_QUESTIONS:
- APScheduler integration mode: `AsyncIOScheduler` (shares the bot's asyncio loop) vs. `BackgroundScheduler` (separate thread pool requiring `asyncio.run_coroutine_threadsafe` for alert delivery). Planner must pick and document in ADR.
- Kiwi Tequila free-tier rate limits are undocumented — 60-minute polling is assumed safe, but many watches could trigger throttling. Planner should note per-job request pacing (small sleep between watch queries) as a known risk.
